# Plan: Stratum Python SDK Rewrite (Section-Based API)

## Goal
Rewrite the `stratum-python` SDK to mirror the new section-based API architecture of `stratum-api`, replacing the old flat-list `TaskRequest` payload format with the new `whole_image`, `prominent_person`, and `prominent_face` boolean schemas.

## Current Context / Assumptions
- `stratum-api` recently migrated to a single-queue, section-based payload (STRATUM-API-8).
- `stratum-python` currently constructs API requests using a flat list of operations: `tasks=[TaskRequest(operation_id="...", type="...", params={"target": "..."})]`.
- `stratum-python` `AnalyzeImageRequest` and `BatchRequest` currently expect `tasks: list[TaskRequest]`.
- Because the system is still in internal testing, we can introduce these breaking changes to the SDK without needing a deprecation cycle.
- The `stratum-api` returns flattened results using dot-notation keys (e.g., `"whole_image.clip"`, `"prominent_person.bbox"`), so the SDK's result parser (`JobResults`) needs to adapt to this new key structure and appropriately map those keys back to their typed models.

## Proposed Approach
1. **Update Pydantic Models:** Replace `TaskRequest` with `WholeImageTasks`, `PersonTasks`, and `FaceTasks` in `stratum/models.py`. Update request schemas to use these optional sections.
2. **Implement Client-side Validation:** Move the cross-section validations (e.g., `prominent_face` requires `prominent_person`; `depth` requires `seg`) into the SDK models so errors are caught locally before making HTTP requests.
3. **Refactor Client Methods:** Update `StratumClient` and `AsyncStratumClient` signatures (`analyze()`, `submit()`) to accept section configuration objects instead of `operations: list[str]`.
4. **Update Operations Registry:** Refactor `stratum/operations.py` to organize available operations by section (mirroring `SECTION_FLAGS` in `stratum-api`) to correctly calculate credit costs locally.
5. **Update Result Parsing:** Modify `results.py` to parse incoming flattened section keys (e.g., map `"prominent_person.seg"` to the `SegmentationResult` parser) instead of relying on the old `operation_id` map. 
6. **Fix Tests & Documentation:** Update `respx` mocked payloads in the test suite and rewrite the `README.md` usage examples.

## Step-by-Step Plan

1. **Models (`src/stratum/models.py`)**
   - Remove `TaskRequest`.
   - Add `WholeImageTasks`, `PersonTasks`, `FaceTasks` classes with boolean fields default to `False`. Ensure `FaceTasks` contains the newly added `pose`, `seg`, `depth`, `normal`.
   - Update `AnalyzeImageRequest` and `BatchRequest` to:
     ```python
     image_url: str
     whole_image: WholeImageTasks | None = None
     prominent_person: PersonTasks | None = None
     prominent_face: FaceTasks | None = None
     ```
   - Add Pydantic `@model_validator` to enforce section dependencies (face requires person, t5 requires caption, depth/normal requires seg).

2. **Operations & Credit Cost (`src/stratum/operations.py`)**
   - Restructure `OPERATIONS` into a section-based registry or a helper that maps `(section, flag)` to `OperationInfo`.
   - Update `estimate_credits()` to accept the request models (`AnalyzeImageRequest`) and compute costs based on sections (including the `+1` cost for person/face bounding box detection).

3. **Client API (`src/stratum/client.py` & `src/stratum/async_client.py`)**
   - Change `def analyze(...)` and `def submit(...)` signatures:
     ```python
     def analyze(
         self,
         image_url: str,
         whole_image: WholeImageTasks | dict | None = None,
         prominent_person: PersonTasks | dict | None = None,
         prominent_face: FaceTasks | dict | None = None,
         sla_lane: str = "within_minutes",
         timeout: float | None = None,
     ) -> JobResults:
     ```
   - Handle dict-to-model conversion for DX (so users can just pass dicts like `whole_image={"clip": True}`).

4. **Result Parsing (`src/stratum/results.py`)**
   - Update `parse_job_results` to understand keys like `"whole_image.clip"` and `"prominent_person.bbox"`.
   - Map section flags to their parser functions (e.g., `"clip"` -> `EmbeddingResult`, `"bbox"` -> `DetectionResult`).
   - Enhance `JobResults` to allow access via properties like `results.whole_image.clip` instead of just string keys, improving developer experience.

5. **Tests (`tests/`)**
   - Rewrite `respx` mock setups to expect the section-based JSON payloads.
   - Update client calls in tests to use the new `whole_image=...` kwargs.
   - Ensure the dependency validation throws `ValidationError` or `ValueError` appropriately.

6. **Documentation (`README.md`)**
   - Update `StratumClient` initialization and `analyze` examples to show section-based configurations.

## Tests / Validation
- **Unit Tests:** After changes, `pytest tests/` must pass with 100% coverage on the updated schemas.
- **Type Checking:** Run `mypy` or `pyright` to ensure the new method signatures are fully typed.
- **Integration:** Run a quick manual test using the updated SDK against a local instance of the newly updated `stratum-api`.

## Risks, tradeoffs, and open questions
- **Breaking Change:** This completely breaks the SDK interface for any existing scripts. We are accepting this as it's an internal-only testing phase.
- **JobResults Access Pattern:** Currently users do `results["embed_clip_vit_b_32"]`. With the new API returning `"whole_image.clip"`, they will have to adapt. It might be worth building a `SectionResults` wrapper so they can do `results.whole_image.clip.parsed.embedding`.
